# 设置面板重设计方案（已实施）

> 状态：**已在 0.6.0 实施**。本文保留为设计决策记录 —— 它写清了「为什么这么分」和
> 「哪些内容搬到哪一页」，实现后的最终结构见 `docs/architecture.md` §3.28。
>
> 与评审稿的两处差异：① 实施时把「本机 Call Me 服务」一并做了（评审稿只写了前端重排，
> 因为当时还没讨论自部署）；② 「今日时长」按计划搬到了「历史」页顶部。
>
> **2026-11-09 的后续修正（本方案实施之后，别拿下面的旧结论判断现状）**：实测发现
> 「内容分得清」不等于「一屏放得下」，设置窗默认已放大到 **1000×720**（下限 820×560，见
> `architecture.md` §4.1），§11 / §13 里「保持 720×690、不靠放大解决」那两条被推翻；
> 同一轮还改了 Call Me 协议（同一条链接的 GET 返回用法说明、`label` 可省、名称与出处由
> 第一条留言回填），§14 的「不改协议」只描述本方案那一轮的范围。

## 1. 要解决的问题

当前面板已经不是「几个设置项」，而是同时承担了三类任务：

1. **看内容**：实时状态、历史复盘、Call Me 留言。
2. **配功能**：灯、通知、智能体、多机、Call Me、系统。
3. **找帮助**：指南、演示、诊断。

这三类任务混在同一层导航里，造成了几个具体的问题：

- 「开始用」组里同时放着接入、多机、Call Me、指南、演示；它们不是同一种动作。
- `接入` 一页有约十个小节：智能体、自定义智能体、系统信号源、其他信号源、CLI、诊断、测试、局域网、Web 面板、转发入口。用户必须在长页面里辨认功能边界。
- `系统` 一页混着通用偏好、更新、体检、快捷键、日志和备份。
- Call Me 把**服务器配置 → 链接管理 → 留言阅读**纵向堆在一页。配置是低频动作，阅读是高频动作；每次看留言都先经过服务器和链接。
- 未读点现在挂在 `Call Me` 配置页上，而不是挂在用户真正要读的「留言」上。
- 顶部在所有页面重复显示当前聚合和今日时长，挤占页面自己的标题与任务说明。
- `SettingsPanel.tsx` 已超过 5000 行，页面、导航、控件、领域状态都集中在一个组件里。继续加功能只会进一步堆叠。

**结论：这次不能只重排页签，也不能只加折叠。需要把「内容工作区」和「功能配置」分开，并给少数复杂页面增加页内子页。**

## 2. 设计原则

1. **一个页面只回答一个问题。** 全局页签按领域分，页内子页按任务分。
2. **阅读与配置分开。** 留言是内容工作区，不是服务器设置的附录。
3. **高频优先，低频后退。** 已配置用户先看链接和留言；服务器参数退到独立子页。
4. **不藏功能。** 高级能力收进明确命名的子页或折叠区，不塞进无说明的「更多」菜单。
5. **不引入新的视觉语言。** 延续扁平、无阴影、无渐变、1px 分隔线、字号与灰度分层；选中态仍是浅灰底 + 正文字色 + 500 字重。
6. **不改数据与后端。** 本轮是前端信息架构和组件边界改造，不借机重写功能。
7. **局部子页不能比全局页签更深。** 最多两层：全局页签 → 页内子页；不再加第三层导航。

## 3. 推荐方案总览

保留现有单窗口、左栏导航、右侧内容的骨架，把左栏调整为五组加一个沉底系统页：

```text
工作台
  状态
  历史
  留言                 ← 新增，Call Me 的阅读工作区

灯
  外观
  行为
  分组

通知
  提醒
  转发

连接
  接入                 ← 页内：智能体 / 其他来源 / 网络与诊断
  多机
  Call Me              ← 页内：链接 / 服务器

帮助
  指南
  演示

系统（沉底）            ← 页内：通用 / 更新与诊断 / 数据
```

这不是把现有 13 个页签再增加一倍。只有 `接入`、`Call Me`、`系统` 三个复杂页面使用页内子页，其余页面不增加导航层级。

窗口名称、托盘菜单名称暂时仍叫「设置」。本次先改内容结构，不把改造扩大到 Rust 菜单和发布文案。

## 4. 页面布局

### 4.1 整体线框

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ● 执行中   3 组 · 5 会话                                  暂停监控 ○ │
├──────────────┬───────────────────────────────────────────────────────┤
│ 搜索…        │ 留言                                      全部已读    │
│              │ 阅读外部智能体通过你的链接留下的建议。                │
│ 工作台       │                                                       │
│   状态       │ [全部 3] [文章 A 2] [文章 B]                          │
│   历史       │ ────────────────────────────────────────────────────  │
│   留言 ●     │ ● 文章 A · Claude · 3 分钟前                          │
│              │   第三节的论证还可以再具体一些……                      │
│ 灯           │ ────────────────────────────────────────────────────  │
│   外观       │   文章 B · 其他智能体 · 昨天                          │
│   行为       │   ……                                                  │
│   分组       │                                                       │
│ 通知         │                                                       │
│   提醒       │                                                       │
│   转发       │                                                       │
│ 连接         │                                                       │
│   接入       │                                                       │
│   多机       │                                                       │
│   Call Me    │                                                       │
│ 帮助         │                                                       │
│   指南       │                                                       │
│   演示       │                                                       │
│ 系统         │                                                       │
├──────────────┴───────────────────────────────────────────────────────┤
│ 退出                                                                 │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.2 顶部与页头

- 顶部只保留**全局状态**：状态点、聚合状态、组数 / 会话数、暂停监控。
- 「今日各状态时长」从全局顶部移到「历史」页顶部。它是回顾数据，不应在每页占一行。
- 每个内容页有统一页头：
  - 页面名；
  - 一句任务说明，解释「这一页能做什么」，不复述实现细节；
  - 页面级主操作（如「全部已读」「添加」「刷新」）放右侧。
- 页面级错误仍就近显示在对应操作下面，不做全局 toast。
- 暂停和退出的位置不做本轮改造；暂停若移到顶部，左栏底部要相应删除，不能出现两份。

### 4.3 页内子页

只对复杂页面使用，形式为一行局部分段导航，位于页头下方：

```text
接入
把智能体和本机信号源接到 SignalHub。
[智能体] [其他来源] [网络与诊断]
```

要求：

- 使用现有扁平选中语言，不新增彩色 tab、下划线动画或卡片。
- 有明确的 `role="tablist"` / `role="tab"` / `aria-selected` / `role="tabpanel"`。
- 支持左右方向键切换，Tab 键仍进入当前页内容。
- 切换局部子页时保留父页状态，**不得清空未提交草稿**。
- 不为每个子页新增 localStorage 键；应用运行期间记住即可，重开应用回主子页。
- 去掉全局自动扫描 DOM 的 `PageSectionsNav`。局部子页必须是显式配置，不能继续靠 `.section` 数量和 DOM 文本推导航。
- 指南这种纯手册页可以保留显式的锚点目录，但不要求所有长页自动出现 chip。

## 5. Call Me 的重点改造

### 5.1 分成两个全局入口

#### A. 工作台 → 留言（新页，id 建议 `messages`）

只负责阅读：

- 页头：留言、未读数、「全部标为已读」。
- 来源筛选 chips。
- 留言列表：来源、agent、时间、标题、正文、未读点。
- 展开即已读。
- 展开后的操作：打开出处（仍只放行 http/https）、复制全文。
- 空态按原因区分：
  - 未配置服务器：说明 +「配置 Call Me」→ `callme` 的服务器子页；
  - 已配置但没有链接：说明 +「新建链接」→ `callme` 的链接子页；
  - 有链接但暂无留言：正常空态；
  - 筛选后无结果：说明当前筛选没有留言。
- 可提供次级入口「管理链接」，跳 `callme` 链接子页。

**未读红点从 `Call Me` 移到 `留言`。** `Call Me` 配置页不再承担未读提醒。

#### B. 连接 → Call Me（保留 id `callme`）

只负责配置和资源管理，含两个局部子页：

1. **链接**（默认）
   - 顶部一行连接摘要：已连接 / 未配置 / 错误，以及「服务器设置」入口。
   - 来源列表：名称、备注、近 24h / 总数、完整链接、复制、吊销。
   - 新建链接表单。
   - 新建成功后的完整链接与复制入口。
   - 已吊销来源仍按现有规则显示，不改变服务器语义。
2. **服务器**
   - 地址、管理 token、轮询间隔、测试连接。
   - 继续使用「草稿 + 失焦提交」，不能改成每敲一个字符写配置。
   - 保留部署前提说明：自部署、TLS 由反代负责、`CALLME_ADMIN_TOKEN`。

### 5.2 数据与事件不变

- `useCallMe` 仍在面板壳里只调用一次，两个页面共享同一份 `state` 和 `refresh`，不能各挂一个事件监听器。
- `signalhub://callme`、轮询线程、`CallMeConfig`、命令名、已读文件全部不变。
- 留言仍然**不进 Store、不进现有收件箱、不触发系统通知**。
- `callme.ts` 的纯函数继续复用；未读口径不变。

## 6. 接入页拆分

`接入` 保留一个全局入口，页内分成三个任务：

### 6.1 智能体

- 已接入 / 已检测 / 未检测的智能体列表。
- 一键接入、卸载、HTTP 方式切换、试一下、回执。
- Claude Code 的灯上审批开关和适用范围说明。
- 自定义智能体入口保留，但表单收进「自定义智能体」折叠区；错误配置仍必须显示。

### 6.2 其他来源

- 内置采集器（会议、备份）。
- 系统信号源清单。
- 收到过上报但不在已知清单里的自定义来源。
- 只用命令行的接入方式与可复制命令。

这一页的名字要说明它既包含「其他上报来源」，也包含「非标准接入方式」，不要叫「高级」这种没有语义的标题。

### 6.3 网络与诊断

- 局域网访问及重启提示。
- 只读 Web 面板、面板审批及依赖提示。
- 一键诊断。
- 试一下。
- 转发配置入口（保留跳转到全局「转发」，不复制转发表单）。

**不变的安全语义：** 局域网、Web 面板、Web 审批仍默认关；警告只在对应条件成立时出现。

## 7. 系统页拆分

### 7.1 通用

- 开机自启。
- 界面语言。
- 全局快捷键及占用提示。
- 托盘与点击穿透的说明文字。

### 7.2 更新与诊断

- 系统体检。
- 版本与更新。
- 打开配置目录、打开日志。
- hook 日志尾部。

### 7.3 数据

- 配置导出。
- 配置导入。
- 导入结果和错误仍明确显示；不能为了页面简洁削弱 Rust 校验路径。

## 9. 前端组件拆分建议

目标不是把 5000 行机械切成十几个文件，而是让**页面状态回到页面里**。

建议结构：

```text
src/components/
  SettingsPanel.tsx              # 壳：导航、全局状态、错误出口、退出、共享 CallMeState
  CallMePage.tsx                 # 删除或改成兼容导出，不再保留三合一页面
  settings/
    navigation.ts                # Tab、分组、别名、合法 id、搜索匹配
    SettingsPage.tsx             # PageHeader / LocalTabs 等共享布局
    controls.tsx                 # Row / Switch / Slider / RowLabel
    StatusPage.tsx
    HistoryPage.tsx
    MessagesPage.tsx
    LookPage.tsx
    BehaviorPage.tsx
    GroupsPage.tsx
    AlertPage.tsx
    HooksPage.tsx
    ConnectPage.tsx              # 只负责局部子页和接入页共享状态
    MachinesPage.tsx
    CallMeSettingsPage.tsx       # 链接 / 服务器两个子页
    GuidePage.tsx
    SystemPage.tsx               # 通用 / 更新与诊断 / 数据
```

职责要求：

- `SettingsPanel.tsx` 不再持有每个页面的草稿、探针结果、展开状态。
- 多机草稿与健康状态移入 `MachinesPage`。
- 智能体接入、回执、诊断等状态移入 `ConnectPage`。
- 更新、体检、备份等状态移入 `SystemPage`。
- `settings` / `patch` / `reportError` / `navigate` 可用一个轻量 context 或明确的公共 props 提供；不引入 Redux 等状态库。
- `m` / `lang` 继续使用现有 i18n hooks，不通过长 props 链传递。
- 共享 `Row` 的可访问名称机制必须保留。
- 切换全局页签仍可重挂页面；切换局部子页时，父页保持挂载，避免丢草稿。

## 10. 导航、搜索与兼容性

### 10.1 页签 id

- 新增 `messages`。
- `callme` 保留，含义收窄为「Call Me 配置」。
- 现有 `status` / `history` / `connect` / `demo` 等 id 不改名。
- `signalhub.settings.tab` 中已有的合法值继续有效；非法值仍回退到 `status`。
- `settingsIntent.ts` 的纸条机制不变，`open_settings` 仍不带参数。

### 10.2 搜索别名

- `messages`：留言、收信、评论、反馈、call me、callme、message、feedback。
- `callme`：Call Me、服务器、链接、来源、部署、token、server、source。
- `connect` 的别名覆盖三个局部子页：智能体、采集器、CLI、局域网、Web 面板、诊断等。
- `system` 的别名覆盖通用、更新、日志、导入导出。

搜索仍回答「去哪一页」，不升级为全文搜索。若后续需要直达局部子页，再让导航目标支持 `{ tab, subTab }`，本轮不强制。

### 10.3 不应改变的行为

- 状态空态仍能去指南和演示。
- 指南仍能去接入。
- 接入仍能去转发。
- Call Me 空态能去对应配置子页。
- 所有设置仍走 `updateSettings` → Rust `persist_settings`，导入仍走 Rust 校验。
- 新增页面不得导致隐藏窗口里的所有页面同时起定时器或发网络请求。

## 11. 视觉约束

必须继续遵守：

- 无阴影、无渐变、无发光、无装饰性 accent 竖条。
- 不把每节包装成圆角卡片。
- 分隔靠 1px 细线，层次靠字号、字重与灰度。
- 全局页签、局部子页、单选控件的选中语言保持一致。
- 未读仍是 5px 小点 + 500 字重，不做整行底色。
- 长链接、token、命令和日志继续可选择、可复制。
- 键盘焦点环、减少动态效果、窗口最小尺寸下的可用性不能回退。
- 窗口默认尺寸保持 720×690、可调整；不靠单纯放大窗口解决信息架构问题。

## 12. 实施顺序与提交建议

每一步都要可构建、可测试，不做一次性大改写。

### 提交 1：先拆组件，不改导航

`refactor(settings): 拆分面板壳、共享控件与页面组件`

- 把现有页面和领域状态搬到对应组件。
- 暂保留当前页签和页面内容顺序。
- 验证所有设置写入、草稿、测试按钮和深链不变。

### 提交 2：建立新导航与页头

`feat(settings): 按工作台、灯、通知、连接、帮助重排导航`

- 引入单一 `navigation.ts`。
- 调整分组、页头、全局顶部信息。
- 用显式 `LocalTabs` 替换全局自动 DOM 小节导航。
- 今日时长移到历史页。

### 提交 3：拆 Call Me

`feat(callme): 留言阅读与链接配置拆页`

- 新增 `messages`。
- `CallMePage` 拆成 `MessagesPage` 与 `CallMeSettingsPage`。
- 未读点移到留言。
- 两个页面共享一次 `useCallMe`。

### 提交 4：拆接入与系统

`feat(settings): 接入与系统页改为局部子页`

- 接入三子页，系统三子页。
- 保留所有安全提示、诊断和高级入口。
- 清理不再使用的 CSS 与组件。

### 提交 5：测试与文档

### 13.2 手工验收（必须真窗口）

实施者需要明确告诉用户运行 `npm run tauri dev` 验收，不能用构建通过代替视觉验收。

重点路径：

1. **Call Me 新用户**：未配置 → 留言空态 → 配服务器 → 建链接 → 复制链接。
2. **Call Me 老用户**：出现未读 → 左栏「留言」有点 → 一次点击到留言 → 展开已读 → 打开出处 / 复制。
3. **链接维护**：不看留言也能直接到 Call Me → 链接，完成复制和吊销。
4. **智能体接入**：接入、切换 HTTP、试一下、回执、审批、自定义表单都可达。
5. **网络安全项**：局域网、Web 面板、Web 审批的提示条件与之前一致。
6. **系统**：更新、体检、日志、导入导出均可用；坏导入文件仍明确报错。
7. **导航**：搜索、回车、Esc、上次页签、纸条深链、状态空态入口均正常。
8. **输入**：服务器 / token / 多机 / 自定义智能体草稿不因局部子页切换丢失。
9. **可访问性**：键盘走完局部子页和表单，焦点可见，开关有可访问名称。
10. **观感**：720×690 与最小窗口下均无重叠、双滚动条或被裁切内容；中英文各扫一遍。

## 14. 明确不做

- 不把留言并入现有收件箱。
- 不改 Call Me 服务器协议、存储、限流、已读模型。
- 不为留言增加系统通知。
- 不改 `Settings` JSON 字段、Rust 命令名或 HTTP API。
- 不重写灯、通知、转发等业务逻辑。
- 不引入路由库、UI 组件库、全局状态库或新主题。
- 不用「高级」「更多」作为杂物抽屉。
- 不为了简洁删除诊断、回执、安全提示或高级配置。

## 15. 评审时需要确认的三个点

推荐默认值如下；若评审不特别修改，实施时按此执行：

1. **留言独立到「工作台」，Call Me 保留为配置页。** 推荐。它解决本次最明确的高频 / 低频混杂。
2. **接入和系统使用页内子页，而不是继续增加全局页签。** 推荐。导航最多两层。
3. **今日时长移到历史页，全局顶部只保留当前状态。** 推荐。让每页标题服务当前任务。

若这三点通过，后续实施无需再另行设计，可直接按第 12 节顺序执行。
