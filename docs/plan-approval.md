# 审批做深：从「能点」到「敢点、点得准、点得少」

> 现状见 `docs/plan-round4.md` 的 C3 一节。本文只讨论**在此之上继续做什么**，
> 以及为什么有些事**不做**。

## 0. 现状边界

- 只认 Claude Code 的 `PermissionRequest`；默认关（`approve_tools`）。
- 等 45 秒（配置里写 60），超时 / 被顶掉 / 开关关 / 绑局域网，一律回 `{}` 交回终端。
- 详情超过 240 字符算截断，**只能拒绝**（规则在 `Registry::decide` 里挡，界面绕不过）。
- 详情只进本地界面；状态上报只发短词；审批端点要 token。

**进度**：第一期 A1 / A2 / A3 已完成（2026-11），验收见各条。A7 及之后未动。

## 1. 四条不能破的铁律

1. **永不自动放行**（唯一例外：用户显式「记住」过的精确目标，见 A6）。
2. **看不全就不给放行**。
3. **详情只进本地界面**，状态上报只发短词。
4. **超时 / 异常一律交回终端**，绝不阻塞 agent。

任何一项新功能，只要和这四条冲突，就改功能，不改铁律。

## 2. 第一期：把「判断质量」做上去（低风险）

### A1. 审批历史 / 审计（已完成）

**痛点**：离开回来不知道批了什么；出事要回溯「谁放行的 `rm -rf`」。

**形状**
- 每日 `~/.signalhub/approvals/YYYY-MM-DD.jsonl`（保留 30 天），启动时轮转。
- 字段：`ts_ms / session / agent / tool / target / detail(截 200) / truncated / decision / reason / source / waited_ms`。
- `decision`：`allow` / `deny` / `expired`。`source`：`lamp` / `api` / `web` / `system`。
- 界面：设置 → 历史页，统计条下面加一段「审批记录」。

**成本**：中。**风险**：低（只写本地）。

**验收**：允许 / 拒绝 / 超时都留痕；重启后仍在；30 天轮转；关掉审批开关后不再记录。

> **与计划不同**：原计划是「内存环形缓冲 500 条 + 文件」，实现里**只有文件**。
> 环形缓冲的价值是「重启后还在」——而文件本来就在，多一份内存副本只是多一处
> 会和磁盘不一致的状态。读的时候只读**最近两个文件**（一条记录只会落在今天或
> 昨天），条数上限放在命令那一层（`get_approval_history` 夹到 500）。
>
> **另一处**：`source` 多了 `system` 一个值 —— 超时 / 被顶掉 / 会话结束都不经过
> 任何界面，记成 `lamp` 或 `api` 都是假的。
>
> **落盘前再截一次**：界面看的是 240 字符（`DETAIL_KEEP` 之外的那份），盘上只留
> 200。屏幕要「现在看全」，磁盘要「以后大概知道」——`API_KEY=…` 不该永久躺在
> 硬盘上。文件按 `0o600` 建、目录 `0o700`，和 token 同档（有单测钉住）。

### A2. 拒绝理由（已完成）

**痛点**：现在拒绝只给模型一句「问用户」，它下一步还是瞎试。

**形状**
- 拒绝默认仍是一键（不逼用户选）。
- 旁边一个小箭头展开三个预设：「太危险」「换更安全的做法」「先解释再试」，外加自定义。
- 每个理由映射成一句英文 message 进模型上下文（模型读的是英文，界面显示中文）。
- 自定义文本截到 200 字符。

**成本**：低。**风险**：低（只影响拒绝那一侧）。

**验收**：带理由的拒绝，`hookSpecificOutput.decision.message` 是那句话；默认路径逐字节不变。

> **认不出来的理由键一律退回默认那句**，不是报错也不是空字符串 —— 拒绝不能因为
> 参数写错而失效。自定义理由全空白时同样退回默认（否则模型会收到一句空话）。
>
> **自定义输入只在收件箱里有**。气泡那条 132px 的高度放不下输入框，硬塞进去就是
> 把「一键拒绝」变成「先滚一屏」；气泡只给三个预设，要写字就开收件箱。

### A3. 危险命令强调 + 按住确认（已完成）

**痛点**：误点「允许」跑 `rm -rf`。

**形状**
- 对命令类工具做保守分类：`rm -rf`、`git push --force`、`git reset --hard`、
  `DROP TABLE` / `TRUNCATE`、`curl | sh`、`mkfs` / `dd if=`、`chmod 777`、`sudo`。
- 命中时气泡顶部一条红色横幅，一句人话（「这条会删数据」）。
- 「允许」改成**按住 800ms** 才生效；拒绝仍一键。
- **只强调、不拦截、不自动拒绝**；误报的代价只是多按一下。

**成本**：低。**风险**：低。

**验收**：`rm -rf /tmp/x` 有横幅且要按住；`npm test` 没有；拒绝不受影响。

> **分类结果和「能不能放行」是两件事**，代码里刻意分开：`danger` 只决定横幅和
> 按不按，`truncated` 才决定能不能放行。有一条用例（`danger_does_not_change_allowability`）
> 专门钉这个，因为把两者混在一起的最短路径是「危险的直接不给放行」——那是替用户
> 做决定，越界了。
>
> **返回的是稳定的键**（`delete` / `force-push` / …）而不是句子：文案要翻译、会改，
> 键不变。界面拿到不认识的键就**不画横幅**（`dangerLabel` 回 `null`）—— 不画比画一条
> 错的强。
>
> **只认命令类工具**。拿路径去匹配 `rm -rf` 的后果是一个叫 `rm -rf.md` 的文件把横幅
> 点亮，而这恰恰会让用户开始无视横幅。
>
> **只按住「允许」**。拒绝永远一键：危险的东西，让人更容易说「不」才对。

### A7. 上下文增强

**痛点**：「写这个文件」看不出要写什么。

**形状**
- `Edit` → `file_path · +12 −3` + 3 行预览（payload 里有 `old_string` / `new_string` 时）。
- `Write` → `file_path · 新文件 / 覆盖 · N 行`。
- `Bash` → 命令全文 + `cwd`。
- 放不进 240 字符的照旧标截断、不给放行。

**成本**：低-中（只改 `hookmap::approval_detail`）。**风险**：低。

## 3. 第二期：打通「不在桌前」

### A4. 手机审批

**痛点**：手机上看得见、点不了。

**形状**
- 面板用同一个 `?t=` token 拉 `/v1/approvals`，POST 决定。
- 新增开关 `web_approve`（默认关）。
- **前置**：`require_auth` 现在拒绝一切带 `Origin` 的请求，而浏览器同源 POST 也带
  `Origin` —— 必须先改成「`Origin` 与 `Host` 同源则放行，跨源仍拒绝」。

**关键取舍**：详情本来是「只进本地界面」，手机审批必须展示它 —— 所以这个开关是
**显式扩大暴露面**。关着时面板仍然只读、连详情都不拉。

**成本**：中。**风险**：中（token 在 URL 里，手机丢了等于丢了审批权）。

### A5. 跨机审批

**痛点**：远程会话卡在权限请求，人在 hub 前。

**形状**
- hub 轮询对端 `/v1/approvals`（对端 token 已有），id 命名 `{machine}:{id}`。
- 决定 POST 回对端；气泡加机器徽章，跳转仍禁用。
- 截断规则由**对端**执行（hub 只转发，不替它判断）。

**成本**：中-高。**风险**：中（多一跳网络，超时 / 重试要处理好）。

## 4. 第三期：减少重复（先验证再动手）

### A6. 精确白名单（「记住这个目标」）

**痛点**：同一个 `npm test` 一天问八遍。

**形状**
- 允许时勾「记住」，作用域 = 本会话（默认）/ 永久。
- 只存 `(agent, tool, target)` **精确字符串**；命中直接放行、不弹气泡，但记为
  `auto` 进历史。
- 硬规则：截断的永不记住；不支持前缀 / 通配；设置里可逐条撤销；默认关。

**这是唯一一处推翻 C3「不做白名单」的地方** —— 理由是用户显式点过「记住」属于
委托，不是替用户决定。**如果 A1–A5 跑下来重复率不高，这项就不做。**

**成本**：中。**风险**：高（写宽了就是灾难）。

### A8. 审批统计

每天次数、中位等待、允许 / 拒绝 / 超时比例。依赖 A1，成本低。

## 5. 明确不做

- 通用表达式 / 通配白名单（配置地狱 + 绕过风险）。
- 「自动批准一切」开关（违背产品立场）。
- 团队多级审批（不是这个产品的用户）。
- 用 LLM 生成拒绝理由（隐私 + 不可预测）。
- 拦截 `PreToolUse`（会拦下本来不需要批准的事）。

## 6. 顺序

`[A1 → A2 → A3] → A7 →（改同源鉴权）→ A4 → A5 →（看数据）→ A6 → A8`

方括号里是**已完成**的第一期。下一步是 A7（上下文增强），它只改
`hookmap::approval_detail` 一个函数，且直接影响 A1 那份历史里 `detail` 那一格
到底有没有用 —— 先做它，再决定第二期怎么走。

一句话：**第一期让「看一眼就能决定」，第二期让「不在桌前也能决定」，第三期才
考虑「不用决定」。**
