# 信号中枢 4 号计划（提案）：从「Agent 信号灯」到「桌面信号中枢」

> 2026-10-16 起草。**这是一份提案，不是已批准的施工图** —— 等你勾选方向后再逐项开工。
> 目标：让信号中枢不止服务 AI Agent，而是成为**桌面上那个「谁在忙 / 谁在等我 / 系统在干什么」的唯一入口**；
> 同时把「更易用」落在具体的小改动上（第一项就是解决你今天的困惑）。
>
> 调研来源分三类标注：**【已验证】**（我实际打开过官方文档/仓库）、**【调研】**（子代理检索到，附链接）、**【待实测】**（本机可验证但还没测）。

---

## 0. 一句话结论

现在最大的两个「不实用」不是功能少，而是：

1. **接入是黑盒** —— 点完「接入」之后，你看不到「它到底有没有在报」。今天你问「opencode 怎么还是无法接入」，根因就在这里：
   文件是新的、opencode 日志里加载成功、app 自检说「已存在且命令相同」、只是**界面没有把「最近一次上报」显示给你**，而当时 app 还没在跑。
2. **信号源只有 Agent** —— 而 HTTP 上报接口（`POST /v1/state`）本来就是通用的，缺的是「信号源」这个概念和几个系统采集器。

**共性结论（直接可用）**：
- 「无信号」必须**显式**表达（灰/黄 + 文案），不能默认绿灯 —— 这正是我们今天缺的。
- 聚合要**最差优先**，且**红黄受保护**（不能被 finished 覆盖）—— 现有 `Signal::priority` 已是这个思路，可以在 UI 文案上说明。
- 插件/上报协议越简单越好（stdout 一行 / 一个 POST），**任何脚本都能当信号源**。
- hook 一律 fail-open，超时要短，绝不能因为信号中枢把 agent 挂住。
- 变更前**备份 + diff**（现有 `install hooks` 已有备份思路，可以显式给 diff）。

### 1.2 Tauri 设计美学（【调研】）

- 案例：**Cap**（https://github.com/CapSoftware/Cap，Tauri v2 + nspanel 浮层 + 独立的录制控制 HUD）、**Handy**（https://github.com/cjpais/Handy，常驻 + 全局快捷键 + push-to-talk）——共同点是**主窗口克制、把「控制面」做成独立小窗**，而不是把所有东西塞进一个窗。
- 可用的包：`window-vibrancy`（macOS 毛玻璃）、`tauri-plugin-positioner`（把窗贴到托盘/边缘）、`tauri-nspanel`（真·NSPanel 浮层，非激活面板）、托盘 API、`global-shortcut`、`autostart`、`store`、`single-instance`、`updater`。
- macOS 限制：Tauri 的托盘是 NSStatusItem，**能**做菜单+图标，**不能**做自定义菜单栏视图（不是 SwiftUI 的 MenuBarExtra）；Windows/Linux（AppIndicator）行为有差异 —— 所以「信息密度」还是得靠悬浮灯窗口，而不是托盘。

### 1.3 前端与能耗（【调研】+【待实测】）

- **透明 + always-on-top 的常驻窗口在 macOS 上可能触发每帧合成**（子代理引到 tauri issue #15471，称 GPU 功耗可达数倍）。**本机没测过，所以写成第一步实测**。
  本项目已有两条相关红线（「动画只动 opacity」「done 不闪」），方向是对的，但**从未量过数字**。
- 事件推送：现在是广播全量快照（`app.emit("signalhub://state", …)`），安静时也在发；可加「**没变就不发** + 合并 100ms」。
- 交互：命令面板（⌘K）对 9 个页签的设置窗收益很大；`prefers-reduced-motion` 已有 ✓。
- 质量：视觉回归（Playwright `toHaveScreenshot` / Vitest）能兜住「几何两处真值」这条红线；i18n key 校验测试。

## 2. 现状盘点（避免重复提案）

**已经有**：8 个 agent 接入（Claude Code / Codex / Cursor / Gemini / Goose / opencode / Pi / Hermes）；多信号灯 + 分组 + 拖拽排序 + 就地改名；悬停摘要 + 右键菜单（灯 / 组两级）；暂停；离线补报（spool）；转发（HTTP + 本地命令 + 日志 200 条）；桌面通知 + 声音 + 通知权限；统计 + 历史（按天）；时间线；双语；自动更新（仅 macOS）。

**缺口**（本计划要补的）：
| 缺口 | 影响 |
| --- | --- |
| 接入页没有「回执」（谁在报 / 最后一次多久前） | 就是今天的困惑：接入成功与失败看起来一样 |
| 没有「试一下」 | 无法 30 秒内自证链路通 |
| 状态源只有 agent | 「系统对接」无处落脚 |
| 没有只读 Web 面板 | 不能离开电脑看（手机/平板） |
| 没有任何「反向通道」 | 灯只能看，不能点回去改变什么（审批/专注） |
| 无「人」的信号 | 番茄钟/开会/离开这类场景无法表达 |

## 3. 提案 A：让「接入」看得见（最小改动、最高性价比，建议先做）

**A1. 接入回执（每行显示「最近一次上报」）** —— 小
- 目标：接入页每个 agent 行显示 `最近上报 12 秒前 · 今天 348 次` 或 `已接入 · 从未上报`。
- 做法：数据源用已有的 `~/.signalhub/hooks.log`（每次 hook 调用都写一行）；新建一个 `last_seen.rs` 或在 `stats.rs` 里加聚合（agent → last_ms / count_today）；前端 `useAgents` 顺带取。**不引入新数据库**。
- 坑：`hooks.log` 会轮转，解析要容错；「从未上报」和「app 没在跑」要分开说（app 没跑时用 hook 日志也拿不到新的，所以文案要写成「自上次启动以来」）。
- 验收：故意卸载某个 agent → 该行立刻显示「已接入（文件在）· 从未上报」；真的用一次 → 数字在 2 秒内更新。
- **这一条直接回答你今天的问题。**

**A2. 「试一下」按钮（30 秒自证）** —— 小
- 点击后：app 自己往该 agent 的会话注入 `idle → working → done` 三条信号（或走一次真实的 hook 命令，若已配），灯当场演示一遍。
- 坑：要明确标注「这是内部测试，不代表 agent 真的在跑」；测出的会话不要留在历史里（用 `signalhub-test-*` 会话名 + 测完自动 clear）。

**A3. 一键诊断（可复制文本）** —— 小
- 打包：命令是否在 PATH、配置文件路径 + 内容、最近 20 条 `hooks.log`、app 端口/token 是否存在、当前是否有 app 在跑。现在的 hooks 日志说明已经很好了，缺的是「一键拿到」。
- 顺带：把「没有 app 在跑 → 事件会进 spool，重启后补报」这条已经实现的行为在界面上说出来（今天你遇到的就是这个）。

**A4. Claude Code 默认改用 HTTP hook（`type: "http"`）** —— 中，**但价值最大**
- **【已验证】** Claude Code 支持 `type: "http"` 的 hook：事件 JSON **作为 POST body** 发到 URL，**返回值用 HTTP 响应体 JSON** 表达决定；字段有 `url` / `headers` / `timeout` / `onFailure`；另有 `allowedHttpHookUrls` 白名单（**只有定义了才生效**）。官方文档：https://code.claude.com/docs/en/hooks#http-hook-fields
- **为什么这是「易用」的关键**：现在最大的接入失败源是「命令不在 PATH」（`signalhub` 没装好 / GUI 启动的 PATH 和你 shell 里不一样）。HTTP 方式**不需要任何 PATH 上的东西**，直连 `http://127.0.0.1:PORT/v1/hooks/claude-code`。
- 新增端点：`POST /v1/hooks/{agent}`（**仅绑定 127.0.0.1；report-only；body ≤ 64KB；无 token**，理由见红线）；把 CC 的 `hook_event_name` 映射成状态：`SessionStart→idle`、`UserPromptSubmit→thinking`、`PreToolUse→working`、`PermissionRequest / Notification→permission`、`Stop→done`、`SessionEnd→clear`；`session_id`、`cwd`、`permission_mode` **【已验证】**都在 payload 里（`agent_id/agent_type` 也在，可区分子代理）。
- 坑：① 必须 `timeout: 5` + `onFailure: "continue"`，**绝不能** block agent；② 映射表要按**真实 payload** 逐条验证后再写进文档（沿用本项目「只写验证过的映射」纪律）；③ 保留现有 CLI 方式作为备选，安装时给用户一个「命令方式 / HTTP 方式」选择，不静默改写已有配置。
- 验收：把 `~/.local/bin/signalhub` 临时移走，HTTP 方式仍能点亮灯；CC 里 hook 超时/失败时 agent 行为完全不受影响。

## 4. 提案 B：系统对接（不止 Agent）

**B1. 把 `agent` 泛化成「信号源 source」** —— 中
- 数据模型向后兼容：现有上报的 `agent` 字段保留，新增 `source: "system"`（缺省 `"agent"`）。接入页分成三组：**AI Agent / 系统 / 自定义**。
- 好处：一个概念换来后面所有系统采集器的统一入口；`/v1/state` 契约不变。

**B2. 内置采集器（每个 = 一个开关 + 一个测试）** —— 建议先做 2 个样板
- **会议中**（macOS：麦克风/摄像头占用）→ 「会议」组，开会时自动变蓝/静音通知。
- **Time Machine 备份中**（`tmutil status`）→ 「备份」组，跑完自动 done。
- 其它候选（每个都给实现路径 + 可信度）：专注/勿扰（Focus）、屏幕锁定/休眠（自动「离开」）、长命令（给用户一个 `signalhub run -- <cmd>` 包装器）、媒体播放（Linux MPRIS ✓ / Windows SMTC ✓ / macOS 无公开 API，**平台差异**）、低电量、日历事件（EventKit 需授权）。
- 坑：采集器**只读系统状态**，不读文件内容；间隔 ≥ 5s；任何一个采集器崩了不能影响主进程（独立线程 + 吞错 + 记 hooks.log）。

**B3. 只读 Web 面板 `/`** —— 中
- 手机/平板打开 `http://<mac>:<port>/?t=<token>` 看灯 + 最近事件；复用 `/v1/state` 快照，纯静态单页。
- **默认只绑 127.0.0.1**，要局域网访问必须在设置里显式打开（并显示「同一 WiFi 下任何设备都能看」的警告）。这是「拓展使用场景」最直观的一步。

**B4. 极简规则（只做 3 个预设，不做表达式引擎）** —— 中
- `permission 持续 > 60s → 手机推送`；`有会话在跑 → 自动暂停通知`；`组=会议 → 灯变蓝 + 静音`。
- 现有「转发」是逐条全量；规则如果做成通用 DSL 会违背「宁可少而精」，所以**只做预设 + 开关**。

## 5. 提案 C：交互互动（灯不只是看的）

**C1. 灯上/组上的动作扩展**（右键菜单已有 ✓，加动作）—— 小
- 单击灯 = 清除当前最差组；长按 = 静音该组 10 分钟；菜单加「专注 25 分钟」「离开」。
- 隐藏收益：**让信号中枢对「人」也有用**，不只是 agent。

**C2. 全局快捷键**（`tauri-plugin-global-shortcut`）—— 小
- 默认：`⌥⇧L` 显示/隐藏灯、`⌥⇧M` 静音、`⌥⇧0` 清空。冲突要检测 + 提示占用。

**C3. 从灯上审批（旗舰，但放二期、默认关）** —— 大
- **【已验证】** Claude Code 的 `PreToolUse` / `PermissionRequest` hook 可以返回 `permissionDecision: allow | deny | ask | defer`（还有 `updatedInput` / `permissionDecisionReason`）。文档：https://code.claude.com/docs/en/hooks#permissionrequest
- 玩法：灯变黄 = 有工具调用在等确认 → 点灯弹出小气泡「将执行：`rm -rf build/`」→ 允许/拒绝 → 用 hook 的 HTTP 响应把决定回给 CC。
- **代价必须说清楚**：hook 会**挂住那次工具调用**直到你点击或超时（所以要给短超时，超时自动返回 `ask` 交回 CC 自己问）。
- 安全：① 默认关闭，且**每次开启只对当前会话生效**；② 审批端点要求 token（与 report-only 端点分开）；③ 只允许「白名单动作模式」，拒绝规则永远优先。**这是全计划唯一会改变 agent 行为的功能**，所以放二期。

**C4. 手动状态 / 番茄钟 / 离开** —— 小
- 「专注 25 分钟」= 一个倒计时占一盏灯（到点提醒并转 done）；「离开」一键；「开会中」手动。
- 让信号中枢在**没有任何 agent** 时也能用 —— 这是「拓展场景」的最低成本证明。

**C5. 声音细化** —— 小：permission 与 error 用不同提示音；可试听。

## 9. 红线（延续 + 新增）

1. 不自动升级、不自动安装（已定）。
2. **HTTP hook 必须 `onFailure: "continue"`、`timeout ≤ 5s`，任何情况下不阻塞 agent**；report-only 端点无 token 但**只绑 127.0.0.1**、限 body 大小、只能写状态；审批端点（C3）必须 token。
3. 新增外发（WLED / ntfy / Apprise）**默认关**，且**只发状态，不发会话名/路径/命令内容**。
4. 采集器只读系统状态，不读文件内容；单个采集器失败不影响主进程。
5. Web 面板默认只绑 127.0.0.1，开局域网必须显式确认。
6. 不引入通用规则表达式引擎（宁可少而精）。
7. 几何仍是两处真值（Rust + CSS），改一处必须同一次提交同步另一处。

### E1 能耗实测（2026-10-17，**结论：不改结构**）

量的是**已安装的 0.2.4**。E1 要问的是「透明 + 常驻窗口」这套结构本身贵不贵，而
`SignalLamp.tsx` / `styles/lamp.css` / `useNow.ts` 与建窗那几行在 v0.2.4 → v0.2.5 之间
**一行没动**（`git log v0.2.4..v0.2.5 -- <这几个文件>` 为空），所以这些数字对当前代码同样成立。

方法：`ps -o cputime=` 前后取差（比 `top` 采样稳），每组 45–60 秒；`top -o power` 只作旁证。
测之前把窗口状态文件里的 `visible` 全设为 false 再启动，**只留一个灯球窗口**（设置窗的
webview 隐藏着也活着，它的时钟会混进来），测完把原文件恢复回去。

| 情形 | CPU（单核占比） | `top` POWER |
|---|---|---|
| 静止、无任何会话（基准） | 0.50% | 1.9–2.3 |
| `working`（1600ms pulse 无限循环） | 1.02% | — |
| `done` / `off`（无动画） | 0.82–0.89% | — |

**所以不动结构。** 常驻一个透明置顶窗口 + 每秒走一次「已持续」，代价是**半个核的
0.5%**；让灯动起来（这正是这个功能的意义）翻一倍到 1%。而 `done` / `idle` / `off`
本来就是 `animation: none`（`lamp.css`）—— 也就是说**静止时确实什么都不动**，那条
「静止时完全停动画」的预案已经是现状，不需要再做。

那 0.5% 的基准来自 1Hz 的 `useNow` tick（牌上「已持续 45s」每秒要重算一次）。它的
收益是明确的（数字会走），代价是半个核的 0.5% —— 按这个比例不值得为它引入一套
「静止几秒后停走秒、动了再恢复」的机制（那本身还要多一条唤醒路径）。

一个**没被这次测量回答**的问题：`top` 的 POWER 是进程级估算，看不见 GPU / 合成器那边
的代价。真要追到底得用 `powermetrics`（要 sudo）。既然 CPU 侧已经这么低、而且静止状态下
窗口内容压根不变（合成器那边是缓存好的图层，没有新帧要画），就不追了。

### E2 事件合帧（`653a14b`）

### B1 信号源概念（`5fa1e24`）

- `source` 是**纯描述**：只影响接入页怎么分组（AI 智能体 / 系统 / 自定义），不参与聚合、
  分组、TTL、通知、托盘、钩子任何决策 —— 填错或不填，灯的表现一模一样。
- 缺省 `agent`：老 CLI 和手写 curl 都不带这个字段，行为不变。**存字符串而不是枚举** ——
  多一个取值不该让老版本 app 解析失败；认不出来的一律落到「自定义」。老
  `receipts.json` 没有这个字段也读得出来（空串 = 没声明）。
- CLI 的缺省：`hook` → `agent`（那条命令就是给我们装进各家配置用的）、`run` → `custom`
  （包装器是用户自己的东西）、手写的 `signalhub working` 按 `--agent` 推（是我们那 8 家
  的名字就算 agent，否则 custom）。`--source` 永远优先，而且**打错当场报错** ——
  服务端不校验，写错了只会静默落到「自定义」，那是「我明明声明了 system」这种哑谜的
  来源。
- 接入页的「系统」那一节**空着也显示**：它是这个概念唯一的落点，藏起来的话用户在采集器
  做出来之前根本不知道有这条路；空着时顺手把用法写出来。
- 诊断文本新增「其它信号源」一节：不在智能体清单里的上报（用户脚本、别的机器、手写的
  curl）此前在诊断里**一个字都没有**，而「我的脚本到底报没报」正是它要回答的。

### B3 只读 Web 面板（`47a5e4c`）

- `GET /` 一张静态模板，数据由页面里的 JS 去拉 `/v1/state`。所以**页面本身不鉴权、
  也不泄密**：拿不到 token 的人看到的只是一句「token 不对」。
- **默认关**（`web_panel`），关着时 404 并给一句能照做的话。**改完立刻生效** ——
  路由读的是当前那份设置，不像「允许局域网访问」要重启。
- 注入的三样都是**既有事实的搬运**，不新增第二份真值：状态名走 `lang::signal_label`
  （和系统通知同一张表）、颜色走设置里的配色、组名走 `group_meta`。注入前把 `<` 转义成
  `\u003c` —— 颜色和组名是用户可写的字符串，而这段 JSON 嵌在 `<script>` 里。
- 配色的三套在 Rust 侧是**粗粒度投影**（每套的 ok / warn / danger / muted 四个色号，
  而不是十个状态）+ 逐个状态的覆盖。这是一处**刻意的两处真值**，`palettes.ts` 那边留了
  指回来的注释（和几何那条红线同一个道理：改的时候要一起改）。
- 「已持续」按**看的人那台设备的时钟**算（页脚写了这一句），不为此给快照加一个
  「服务端此刻」—— 那是为一行字去改契约。明显不合理的值（负数 / 超过一年）就不显示。
- 设置页放在**接入**页「允许局域网访问」下面：两者都是「从哪能看到 / 报进来」的事。
  链接里的地址取**实际绑到哪了**（`bound_lan`）而不是开关 —— 刚打开还没重启时给一条
  `http://192.168…` 是给不出去的东西（手机上打不开）。
- **真机验证**（无头 Chrome 走 CDP）：正常渲染（标题 / 灯色 / 组牌 / 已持续）、1 秒后
  自己刷新（外面改状态，页面上从「需要授权」变成「已完成」）、不带 token、token 不对。

### D1 物理灯（WLED，只发状态色）（`1e5f567`）

- 位置：**「转发」页最下面一节**，不是新开一个页签。它和出站钩子是同一件事
  （SignalHub 主动往外发），区别只是发的东西不一样 —— 为一个功能多开一个页签的
  成本比这个功能本身还大。这一条和计划里写的「一个『外设』页」有出入，是有意的。
- **发出去的东西只有颜色。** body 里没有组名、没有会话名、没有路径、没有消息内容；
  有一条用例专门钉住「body 里多出了别的字段」。灯可能挂在别人也看得见的地方，而
  WLED 自己的界面会把收到的东西回显出来。
- **不发没变过的颜色**（按「上一次**成功**发出去的颜色」去重）。一次工具调用能推
  几十次状态，而灯只在「变」的时候才需要发；这一条顺带把「灯拔掉之后每秒敲一次」
  挡住了 —— 否则 200 条的日志环形缓冲会在几分钟内被刷满。
- **失败会重试**：2s / 5s / 15s / 30s / 60s，然后放手等下一次状态推送（那时重开一条
  链）。**每次重试都重新读「现在该是什么颜色」** —— 链可能跑了两分钟，发一个过期
  颜色等于把灯钉在旧状态上。收工记的是**真正发出去的那个**颜色，不是「此刻该是
  什么颜色」（两者在重试期间可能已经不一样了）。
- **`on: true`，而且「没动静」是灰色不是关灯。** 灯亮着是它存在的理由（用户关掉它
  多半是想关灯，不是想关掉通知）；而关灯和「应用挂了」从外面看一模一样。不动
  `bri` —— 亮度是用户在 WLED 那边调好的。
- **200 不等于成功了。** 地址敲错一个数字，答话的可能是路由器或者别的 HTTP 服务，
  它照样回 200，界面上却写着绿色的 `ok 200`。所以认 WLED 的 `{"success":true}`，
  认不出来就把响应体开头写进日志（「它到底答了什么」正是用户要看的）。
- **没有开关**：填了地址就发、空着就不发，和钩子一个脾气（`is_configured` 那条）。
  多一个开关只会多出一种「配置看起来在、实际不发」的哑谜。默认列表是空的 = 默认关。
- 顺手把「状态 → 颜色」收成 Rust 侧**一个入口**（`Settings::state_color`）：只读 Web
  面板和物理灯都从那里取，免得两处各写一份配色投影（B3 那处粗粒度表已经搬进去了）。
  配色表本身仍是两处真值（`palettes.ts` 十个状态 / Rust 四个语义档），互相留了注释。
- 日志**和出站钩子共用一份**（`outbound.json` / `hooks.log`，`record` 改成
  `pub(crate)`）：用户只需要一个地方看「我配的东西到底发出去了没有」。界面按
  `WLED <地址>` 这个字符串去对最近一次结果，两边必须一模一样。
- 保存设置时会立刻按当前状态发一次（`apply_settings` 里那一句）—— 那是「填完了到底
  通不通」唯一一次能马上看到的回答。改地址时旧记录会被清掉（否则改回来会因为
  「上次发过这个颜色」而跳过，表现为「改回来了却不亮」）。
- **真机验证**（一个假 WLED + 无头 Chrome 走 CDP）：
  - 启动按当前状态发一次灰色（`#9ca3af`）→ 上报 `error` 变红（`#d0342c`）→ 再上报一次
    `error` **不再发** → 换成 `working` 变绿。三次 POST 的 body 里都只有颜色，上报时
    带的「构建失败」一个字都没进去。
  - 日志：`→ WLED 127.0.0.1:8089  ok 200 success`（和钩子同一份）。
  - 指向一个「回 200 但不是 WLED」的服务 → 记成失败并把响应体写出来。
  - 指向没人听的端口 → 按 0s / 2s / 5s / 15s 重试；灯起来之后那一次就成功了，
    日志里跟着一条 `ok 200 success`。
  - 设置窗（假 IPC 喂数据）：「物理灯」那一节渲染出「灯 1 / 删除 / ✓ 200 success ·
    6s前」和一张「灯 2 / 未填目标」的空卡；点「添加」存下去的是 `{host:""}`、填地址
    失焦存下去的是 `{host:"10.0.0.7"}`（去空白）、删掉的是对的那一张、值没变时再失焦
    不白存一次。

### C2 全局快捷键（`0d2ce7c`）

- 三个动作都作用在**最差的那一组**（紧急度最高的那一组）：`⌃⌥L` 显示 / 隐藏灯、
  `⌃⌥M` 静音 / 取消静音、`⌃⌥0` 清除它的状态。**判据用紧急度而不是显示顺序** ——
  置顶只改显示顺序，而这三个动作的语义是「处理最要紧的那件事」，不是「处理我摆在
  最上面的那块牌」。这条规则（连同 `Store::snapshot_at` 那个排序）有一条用例钉着：
  选错组的表现是「清掉了一个本来没事的组」，很难被注意到。
- **和计划差一个修饰键：⌥⇧ → ⌃⌥。** macOS 上 ⌥⇧+字母 / 数字**是打字符的组合**
  （⌥⇧L = Ò、⌥⇧0 = º），全局注册之后那些字符在所有应用里都打不出来了 —— 而这是
  **看不见**的那种坏（不像「撞车了」会被明说）。⌃⌥ 同样不是任何应用的常用组合，
  也不是「⌘S 那种全民快捷键」。两条规则（带一个主修饰键、至少两个修饰键）各挡一类
  事故，都写进了 `no_shortcut_steals_a_plain_keystroke`。
- **冲突要能看见，这是这一节真正的重点。** 注册失败原来只写一行 stderr（从 Dock 启动
  的话根本没地方看），现在记进状态、在设置 →「系统」页明说「被别的程序占用了」，
  启动时也打一行四个组合（带「（没抢到）」标记）。**不做可配**：真正的故障是被别的
  程序占了，而那件事可配也解决不了 —— 加一套按键录制器只会换来「配置看起来在、其实
  抢不到」，那是这一轮一直在删的那种东西。
- **静音会发一条通告**：静音只影响通知和提示音，灯照常显示那一组 —— 这个动作在屏幕上
  **看不见**。一个按下去什么都没发生的全局快捷键，用户只会再按几次（甚至以为坏了）。
  走的是 `alerts::send_message`（和「已进入点击穿透模式」同一条路，固定静音、无按钮）。
  **清除不发**：那一个看得见（牌立刻没了），再弹一条是多此一举。
- 四个组合（含原有的穿透 ⌥⌘S）连同状态一起收进新的 **`shortcuts.rs`**：常量是唯一真值，
  标签和注册都从它派生（这里曾经有过一份独立的 label 常量并漂移过）。lib.rs 里那套
  label 辅助函数和它的单测跟着搬了过去，lib.rs 因此小了 90 行。
- 界面那几行**从 Rust 拿组合**（`get_shortcuts`）：前端不自己拼键名，否则就是第二处
  真值。字段名有一条 serde 用例钉着（TS 那侧是手写的镜像，不做代码生成）。
- **真机验证**：启动日志 `[signalhub] 全局快捷键: ⌃⌥L / ⌃⌥M / ⌃⌥0 / ⌥⌘S`（四个都
  抢到了）；设置窗（假 IPC 喂数据）在「系统」页渲染出四行，没抢到的那一行带「被别的
  程序占用了」标记，中英各看了一遍。
- **没验证到的**：真的按一下键。合成按键需要辅助功能授权，这台机器没给 ——
  `osascript` 走 System Events 被 TCC 拒（-1743），`CGEventPost` 也没反应；
  而「另一个进程试着注册同一个组合会不会失败」这条路也不成立（Carbon 的
  `RegisterEventHotKey` 跨进程不互斥，连已在用的 ⌥⌘S 都探成「空闲」）。
  动作体里的两个判断（挑哪一组、按一次切换）都有单测，其余几步走的是既有入口
  （`persist_settings` / `clear_group` / `send_message`），没被覆盖的只有那四行接线。

### C4 手动状态（`a8dbd85`）

- 托盘的「手动状态」子菜单：**专注 25 分钟**（牌上出现倒计时，每分钟走一格，到点提醒
  并转 `done`）、**开会中**、**离开**、**清除手动状态**。
- **它们就是普通的一组分**（组名「我」/「Me」，跟着界面语言），走的也是普通上报那条路
  （`Store::apply` + 推送）—— 所以灯、今日统计、历史、只读 Web 面板、转发钩子、物理灯
  全都自动认它。这一条是这一节的全部要点：**没有第二套状态机**，`manual.rs` 里没有一句
  跟渲染有关的话。信号也不新增：专注 = `working`（绿、会动），开会 / 离开 = `idle`
  （灰、安静模式下半透明，牌上那行字说清是哪种不忙）。
- **组名跟着语言**（「我」/「Me」）。所有显示路径都直接用组名，本地化一次就不用给灯、
  Web 面板、分组页各加一次「这个名字要翻译」。代价是换过语言之后旧名字那个组还在
  （TTL 12 小时），所以「设一个新的」和「清除」都把**两个名字一起处理** —— 不然牌上会
  同时挂着「我」和「Me」，或者「清除手动状态」清完还剩一块清不掉的牌。名字表
  （`GROUP_NAMES`）和「每个语言各有名字、两个名字不同」有一条用例钉着。
- **开会 / 离开不动通知设置。** 想「别打扰我」有托盘里的「暂停 / 恢复监控」；把两者
  悄悄绑起来，会让「我离开一下」顺手改掉一个用户没提过的开关。
- **设，不是切。** 再按一次同一个是「重新开始计时」，收掉用「清除手动状态」。三个动作
  都幂等，所以托盘那几项的文案**不用跟着状态变** —— 而菜单里显示的状态正是最容易和
  真实状态漂移的东西（「暂停」那一项也早就刻意不显示开关状态，理由一样）。代价是
  「专注 25 分钟」按第二次会重开一轮，这在菜单文案上是诚实的。
- **倒计时按 deadline 算，不固定睡 60 秒。** 笔记本睡一觉醒来之后，固定睡法会把过期的
  分钟数报出去、那行字再挂一整轮；按 deadline 算则立刻跳到正确的剩余量。抽出来的
  `minutes_left` 是纯函数，`the_countdown_walks_down_to_one_and_then_ends` 把整轮
  25 分钟走一遍（24 → 1 然后到点）—— 少跳一次、最后一分钟写 0、到点那一下没来，三种
  都会红。这是这个功能最容易错的地方，而它没法靠「等 25 分钟」来验证。
- **到点会响**（跟着「提示音」开关，`alerts::send_timer` 是新加的出口）。自己设的倒计时
  到点却悄无声息等于没提醒。两个刻意的选择：**不受勿扰时段影响** —— 勿扰管的是「事情
  自己发生」时的打扰，而这是用户几分钟前亲手设的；**不走告警那条路** —— 那条要一个
  快照、会记「这条通知说的是哪一组」、还带动作按钮，而定时器没有「哪一组」。`done` 本来
  就不是「需要你注意」那一类（`alerts::is_urgent` 只管 permission / attention / error），
  所以也不会因此多弹一条。
- 上报里 `source` 照实写 `custom`：本地注入这条路没人读它（凭证表只在上报服务里写，
  见 `server.rs`），但声明成 agent 会是错的。
- 四个菜单 id 只有一处字面量（`manual.rs` 的常量），托盘那边用常量建菜单、用
  `action_for` 分派 —— 字面量写两遍的话，写错一个的表现是「点了没反应」而且不报错。
- **真机验证**：应用起得来 —— 这一条同时证明了托盘菜单建成功了（`build_menu(...)?` 在
  `init` 里，失败会让 setup 失败、应用起不来），四个快捷键也照常注册。渲染走的是等价
  上报：`signalhub working --agent me --group 我 --message "专注 · 还剩 25 分钟"` →
  `/v1/state` 里出现组「我」、`working`、那行字；换成 `Me` +「Away」也一样，聚合跟着
  变成 `idle`（灰、安静）。
- **没验证到的**：真的点一下托盘菜单。这台机器点不到托盘（菜单栏项要靠合成鼠标事件，
  而合成事件同样没授权 —— 见 C2 那一条）。所以「菜单项 → 动作」那一次跳转只有单测覆盖
  （id 互斥 + `action_for` 映射），动作体本身（倒计时、到点通知）是单测 + 上面那条等价
  上报覆盖的。**专注跑满 25 分钟那条路（每分钟那一跳 + 到点那条通知）没在真机上看见过。**

### C3 从灯上审批（`5f4ca94`）

- **它做的事只有一件**：Claude Code 在「本来就要问你批准某个工具调用」的那一刻
  （`PermissionRequest`）打一个 HTTP hook 过来，灯上弹一条气泡，点「允许 / 拒绝」。
  不做白名单、不做规则、不拦别的工具调用 —— `PreToolUse` 会拦下本来不需要批准的事，
  那是替用户做决定，不是把确认框搬个地方。这条差别是整个功能形状的来源。
- **默认关**（`Settings.approve_tools`）。关着时端点照常回 200 但回 `{}` = 官方协议里的
  「hook 什么都没说」，于是 Claude Code 走它自己的询问流程 —— **装了 hook 也不改变任何
  行为**。这也是为什么关着的那条路上我们连日志都不多写一行。
- **永远不替用户说「允许」**：超时（45 秒）、被同一个会话的新请求顶掉、开关被关掉、
  绑着局域网，四条路一律回 `{}`（交回终端里那个确认框）。
- **看不全就不给放行**。详情超过 `hookmap::DETAIL_MAX`（240 字符）就算截断，那条只允许
  拒绝 —— 规则挡在登记表里（`Registry::decide` → `Decided::NotAllowable`），界面只是
  不画那个按钮，接口绕不过去。这是「白名单动作模式」的落点：一条在灯上看不全的命令
  不该被一键放行。
- **端点要 token**，和免鉴权的上报端点分开（上报那条不能要：它写在用户会被 commit 的
  配置里，而 token 是每台机器一份的秘密）。审批那条替用户做决定，所以必须有凭证。
  装进去的那一条自带 `Authorization: Bearer <token>`，token 从 `~/.signalhub/token`
  读、由 `install_approve` 写进 `~/.claude/settings.json`（卸载会把带 token 的那条一起
  清掉 —— `is_our_http_handler` 因此要认 `/v1/approve/` 这个前缀，只认上报那条前缀的
  后果是「卸载之后 token 还留在用户配置里」）。
- **两个超时，必须一长一短**：写进配置的是 `timeout: 60`，我们内部等 `WAIT = 45 秒`。
  反过来的话对方会先超时，我们那个窗口永远走不满（表现是「灯上的按钮点不动」）。
  两个常量在两个文件里，所以有一条用例专门钉这个关系。`onFailure: "continue"` 仍然
  照写：端点不在时**绝不阻塞智能体**，这是 §9 那条红线的延续，不是例外。
- **命令全文只进本地界面**。气泡里是 `hookmap::approval_detail`（Bash 是命令、Write 是
  路径、其余是紧凑 JSON），而**状态上报仍然只有 `hookmap::tool_target` 那个短词**
  （「执行 npm」），不发通知、不进出站钩子。命令里可能有 `API_KEY=…`，而那是「只发状态」
  那条红线的范围。有两条用例盯着这件事（状态里没有命令全文、气泡里有）。
- **两处与计划不同**（都记在这里）：
  1. **绑局域网时回 `{}` 而不是 403**。计划写的是「和上报端点一致回 403」，实现里改成
     了「什么都不说」。理由：403 在 Claude Code 那边是 non-blocking error（每一次确认框
     都会带一行属于我们的故障），而 `{}` 正好就是协议里那个「没有决定」的答案 ——
     结果完全一样（回终端问），而且不吵。上报端点仍然回 403（那条红线的理由是「别静默
     工作」，而这条端点**本来就该沉默**）。两条都留了日志。
  2. **超时的条目由谁收**：handler 在超时后按 **id** 收（不是按会话 —— 同一个会话可能
     刚又来了一条，按会话收会把新的那条一起带走）。另外 `Registry::list` 会顺手扫掉
     超过 45 秒的条目：请求方中途断开（`curl -m`、Claude Code 被杀）时 handler 那个
     future 直接被丢掉，那条路走不到 `expire` —— 留在表里的表现是**灯上永远挂着一条
     没人等的审批**。这个洞是端到端验证时抓到的（超时回 `{}` 之后列表里还挂着）。
- **灯上的气泡**：每条 132px 固定高（`config::APPROVAL_BUBBLE_H`，和 `lamp.css` 的
  `--bubble-h` 是两处真值），窗口高度 = 原高度 + 条数 × 132，最多画 3 条
  （`MAX_APPROVAL_BUBBLES`）。气泡**绝对定位**在牌子下面，所以折叠态（横排的点）不用
  另写一套几何。气泡里的字不跟着牌面淡（牌淡到一半会把字翻成深色，而气泡底色是实的
  深色 —— 跟着翻就什么都看不见）。变化由 Rust 推（`Registry::on_change` → 前端
  `signalhub://approvals`），并且**顺手重算一次布局** —— 「没人点、超时了」那条路上
  一次状态推送都没有，只广播不重算的话窗口会一直留着一块空出来的地方。
- **端到端验证**（curl + CDP 渲染，全部通过）：无 token → 401；开关关 → `{}` 且不登记；
  开关开 → 请求阻塞、`/v1/approvals` 列出那条（带命令全文与 `allowable`）；点允许 →
  `{"hookSpecificOutput":{"decision":{"behavior":"allow"},"hookEventName":"PermissionRequest"}}`；
  拒绝 → `behavior: deny` 带一句给模型的英文说明；截断的 → 放行被拒、拒绝可行；
  45 秒没人点 → `{}` 且列表自清；`PreToolUse` / `PostToolUse` / `Stop` → `{}` 且不登记；
  局域网开着 → `{}` 并留痕（上报端点仍然 403）。渲染用无头 Chrome + 假 IPC 看过：
  两条气泡（第二条只有「拒绝」+ 一行「这条在灯上看不全」）、`padding-bottom: 274px`、
  点「允许」调到 `decide_approval {id, decision:"allow"}`。
- **没验证到的**：
  - **真的让 Claude Code 打一次这个 hook。** 这台机器上没跑 Claude Code，所以「它会不会
    带 `Origin` 头」这件事仍然未知 —— 带了会被 `require_auth` 拒（静默退回终端询问，
    也就是功能不生效但不出错）。`onFailure: "continue"` 保证最坏情况就是「和没装一样」。
  - **接入页那个开关点下去**（`set_tool_approval` 命令本身）。它和 CLI 的
    `install hooks --approve` 走的是同一个 `hooks::install_approve`（CLI 那条验过了），
    只是多一步 `persist_settings`。开关的**效果**验过（改 `config.json` 后端点行为跟着变）。
  - **灯上气泡在真窗口里的样子**：窗口高度是 Rust 算的，而灯窗的渲染是 CDP + 假 IPC
    看的，两边没有在同一次运行里对过（Rust 那侧的 `approval_area` 只有 `apply_window_size`
    的既有测试覆盖，没有针对气泡高度的用例）。
